# 课程标题优先与一课一目录

## 何时进入，先问什么

用户明确表达实际剪辑意图即可触发，包括“我想剪一个课程长视频”和“这些素材帮我剪成课程”；不依赖`$course-long-video-editing`字面调用。只讨论技能设计、解释方法、更新文档或回顾旧课，不当作新课制作任务。

本次课程标题未知，先询问：**“这次想剪辑的课程标题是什么？”** 已有明确本课标题就沿用，不让用户再说一遍。文件名可以辅助提出候选，但不能未经确认当作课程标题；旧项目/旧课次也不能自动套给新片。标题未定前可查看已提供文件清单以准备归类，不开始ChatCut导入、ASR、粗剪或动画。

## 标题确定后建立固定根目录

`workspaceRoot`是用户当前项目工作区，可能已有Skill交付和多个课程；`courseProjectRoot`是它下面本课独立目录。用户指定的项目父目录优先，否则使用当前任务工作区，不把素材写进技能安装/包目录。

目录名为`YYYYMMDD-课程标题`。日期取用户/客户端本地的本次建项目日期，不能取远端主机UTC日期、原片修改时间或旧课日期。续作从当前会话/用户指定位置/本课记录恢复原目录，跨日仍复用；另一个视频才建立另一个目录。同日同标题且无法判断是续作还是另一课时，先澄清，不混存或覆盖。

```text
YYYYMMDD-课程标题/
├── 原片/
├── 片头/
├── 片尾/
├── 封面/
├── 参考资料/
├── 课程项目.json
└── 创作日志.md
```

五个素材子目录在启动时建齐。`课程项目.json`记录原始建档标题、实际目录名/日期、工作区与本课路径、素材来源/归类、后续原生工程映射；日志从这里开始。保留原始标题；文件系统不允许的字符进行必要兼容处理、过长名称保留可辨前缀与摘要，记录转换结果，不改变课程含义。

可用纯Python标准库助手（无网络、无ChatCut调用）：

```sh
python3 scripts/init_course_project.py --workspace "当前项目工作区" --title "用户已确认的课程标题" --date YYYYMMDD
```

把示例日期替换为客户端本地实际日期。助手以脚本位置找模板，`--workspace`必须明确，不能靠当前cwd猜资料位置；Windows可用`py -3`。没有Python时，用当前文件工具完成同等建目录/记录操作，不阻塞工作。

## 两种来料方式

**先表达意图，没有文件。** 建好目录后给出真实可定位路径和五类放置说明：原片放课程视频，片头/片尾放用户成品，封面放用户图片，参考资料放文档、截图、链接说明等。提醒一次即可，等待素材；不制造示例课程或空占位视频来开始剪辑。

**先给素材，再要求剪辑。** 标题仍先确认；建好目录后助手主动归类、复制并核对，随后说明已放好什么、实际还缺什么。不能让用户把已经给过的资料再搬一遍，也不能先导入临时附件路径再整理。

按用户说明和上下文判断角色：MP4可能是原片、片头、片尾或参考，图片也可能是封面或资料，不能仅凭扩展名分类。用途不明就问这一项；其他明确文件继续处理。用户提供目录时先列出相关文件并保留有意义的内部结构；网页链接可以保存为`参考资料/来源链接.md`，必要的下载/截图使用当前获准工具，不把链接当成本地文件或承诺已下载。

本课默认**复制**用户提供的原文件，避免破坏其他项目/临时交接的来源；明确要求移动时才按其范围移动。校对源/目标大小与内容摘要，记录原路径、分类后相对路径、用途、版本/摘要和待确认项。原件不改写；同名同内容可复用，不同内容另存可辨名称，绝不静默覆盖。不要用指向临时附件/其他项目的符号链接冒充独立归档。

初始化助手也支持显式归类的本地文件清单，清单示意如下（保存到本课或临时工作目录，不放全局Skill）：

```json
{"files":[{"source":"实际本地文件路径","category":"原片"},{"source":"另一实际本地文件路径","category":"参考资料","relativePath":"文档/报告.pdf"}]}
```

```sh
python3 scripts/init_course_project.py --workspace "当前项目工作区" --title "已确认标题" --date YYYYMMDD --assets-json "本次本地文件分类清单.json"
```

分类由助手理解确定；脚本不推断文件角色、不访问网页、不执行来料。清单只接收明确的本地文件；文件夹先由助手列出相关文件，必要时用`relativePath`保留其内部结构。复制后核验SHA256并在本课记录源/目标；失败项说明原因，已成功归档的文件不删除，不据失败继续剪辑。已有用户文件/日志保留，未知非空同名目录须先检查，只有确定属于本课才使用`--adopt-existing`。

## 后续产物全部跟随本课

在这同一个根下按需添加：

| 目录 | 内容 |
| --- | --- |
| `工作文件/字幕/` | 源转写、术语/校对、显示字幕、当前时序与版本 |
| `工作文件/动画/` | 每段当前MG/处理器源码、相对依赖、属性、分镜与绑定 |
| `参考资料/` | 用户资料、真实采集原件、截图/派生、生成插画与来源表；私人记录不直接给学员 |
| `工作文件/证据/` | 检查帧、数据快照、问题与修正、实际导出回执 |
| `预览/` | 当前与历史审核片及版本说明 |
| `交付/` | 实际最终成片、用户封面、学员PDF/文案和适合分发的资料 |

新课程视频使用独立ChatCut工程，从本课稳定路径导入；不能因界面当前打开旧课就沿用旧工程/资产ID。续作使用本课记录的工程，不重复新建。

原生工具支持指定工程包位置时，放入本课`工作文件/ChatCut/`；不支持时保留应用受管位置，并记录项目/时轴ID与工程路径及本课目录的映射，能够导出备份时放本课。不要为满足目录形式而直接移动运行中的工程数据库或缓存。动画源和媒体优先从本课稳定路径导入，不能删除或改名后仍假称引用有效。

建档标题用于稳定目录，后期提炼的上传标题是`publicationTitle`，另行保存。最终标题改变不自动改文件夹名、原生源路径或资产绑定。用户明确要求改目录时，先检查并维护所有引用与当前工程，再验证。

## 开始剪辑的交接点

确认课程标题、本课根目录、五类子目录与已提供文件的归档/待确认记录完成，再开始读取原片画面和当前原生能力，询问未知的粗剪状态并进入后续流程。目录齐全不代表原片可用或素材已齐；缺原片等待，缺片头/片尾/封面按其现有规则继续可独立完成的工作。日志、源/预览/交付均落本课，工作区根只保留跨课索引和技能维护记录。
