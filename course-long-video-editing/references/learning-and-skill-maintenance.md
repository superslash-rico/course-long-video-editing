# 每次剪辑后的经验沉淀与本机Skill迭代

## 已确认的维护政策

完整剪辑结束后复盘：**通用经验和新要求自动更新本机Skill；GitHub公开发布必须先得到用户确认。** 此授权只覆盖该工作流的合理本地维护，不授权发送消息、上传原片/客户资料、改账号或绕过文件权限。当前用户的后续指令/限制优先。

若本次只做局部工作，复盘仅覆盖实际完成部分。先如实记录未完成/未验收，不为了“剪辑完成”标签夸大结果。用户未定稿的建议保留候选，不能写成已认可视觉或已验证方法。

## 哪些进入全局

| 类型 | 保存与处理 |
| --- | --- |
| 明确要求、可泛化且适用范围清楚 | 更新对应规则，替代冲突的旧要求，注明适用模式/条件；用户要求有效不等于实现已通过 |
| 真实失败与已确认修正 | 提炼触发条件、错误后果、修正方法和有意义的回归检查，保留反例；不要只累加“永远禁止” |
| 单课标题/简介/导图/真实截图/来源表/时间码/人物/客户资料/账号/工程ID及用户供片头片尾/封面 | 留在项目，不进入全局规则、模板默认或公开包；供稿不等于授权跨课复用/公开 |
| 未验证猜测或当前工具暂时限制 | 标候选/版本范围/未验证，不冒充普遍规律或自动更换全部工作法 |
| 新固定组件或成功案例 | 只沉淀用户已选定/审核且许可允许的部分；专业动画按最新整体标准完整审核后才作为达标样片，旧局部认可不升级为整体验收 |

复盘格式可复制[记录模板](../assets/records/skill-update-record-template.json)，每条写来源、原规则/新规则、适用边界、实际证据、验证范围和状态。私人请求原文/截图留在项目，不随全局模板传播。

## 实际更新方法

1. 读当前实际使用的技能路径、版本、文件清单和已存在的本机改动；不能从旧日志猜安装位置。将整个现有技能复制到项目内的候选目录，备份旧安装，所有当前课程制作源另存项目。
2. 按本次实际问题小范围修改对应文档/组件；保留完整整体构图与镜头方法的核心细节，清理被替代的默认值、说明与示例，维护名签/金句、人像/录屏分流和粗剪权限边界。新模板不替换无关资产。
3. 增加/改变可复用资源时说明用途、许可、状态，确保相对依赖闭合。新脚本做真实输入/失败边界测试；新视觉需真实当前片检查，不能把静态文档验证写成效果达标。
4. 更新`PACKAGE.json`版本和相关入口/UI说明/验证范围。新能力/流程用minor，兼容修正用patch；不要自动用本次课程名做技能新名字。
5. 更新`assets/manifest.json`。有[rebuild_manifest.py](../scripts/rebuild_manifest.py)时先在候选副本运行预览；旧库存中存在的文件保留用途/许可/状态。新增文件要由本次作者提供明确元数据，不自动将任意二进制认作自有资源；明确删除时使用允许移除选项。默认只读预览，`--write`才写清单。
6. 运行包完整性/相对依赖、相关属性/cues及有必要的实际渲染检查；只有实际收到且适用的封面才做对应检查。修正后重检受影响部分；未改变且仍适用的证据可保留原范围。记录失败和修正，不伪造“所有端到端通过”。
7. 对比现有全局安装与备份基线，确认期间没有他人修改，再仅更新这一技能，核对全部当前文件/版本和默认值。不同既有版本不要让只新增安装器覆盖；用可回滚、保留用户改动的升级流程。权限需当前宿主允许，不能因本政策擅自绕过沙箱。
8. 记录本机已更新、旧备份、实际文件校验及下一轮适用规则。新版文件在新任务/下一次调用中的发现与实际工具连接分别确认；不要复制整份`.codex`或登录配置。

候选目录内重建清单示例：

```sh
python3 scripts/rebuild_manifest.py
python3 scripts/rebuild_manifest.py --metadata "本次项目准备的新增资源元数据.json" --write
python3 scripts/verify_package.py
```

元数据是JSON数组，每项至少包含`path`（技能内相对路径）、`role`、`rights`、`status`，均明确且非空。辅助文件存项目候选目录外；模板/私有原图不因此自动进包。清单脚本不替代独立内容/权利检查。

## GitHub确认与后续版本

本机自动迭代不自动执行push、公开分支/PR、发布release或上传新增资源。准备可审阅的版本变化/资源清单和验证摘要，说明有无隐私/第三方/未验证内容；获得本次明确发布确认后，再按目标仓库实际最新状态同步，核对远端提交、公开范围、下载和检查结果。

GitHub暂未同步不应阻塞用户已授权的本地后续剪辑；交接中明说本机版本与公开版本的差异。新项目若用户要求不改技能，保留项目级复盘并遵循该限制。
