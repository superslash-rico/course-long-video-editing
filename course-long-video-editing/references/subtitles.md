# 添加并校对字幕

**v1.1时序前提：** 先按[接收与粗剪](intake-and-rough-cut.md)确定粗剪状态并完成已授权语音剪辑，按[首尾转场](branding-intro-outro-transitions.md)稳定用户素材的实际合成时间，再以当前时轴校对字幕；素材待补时可先按正文局部坐标校对，不将暂定成片时间记为最终。源ASR可用于粗剪判断，最终字幕定时不能照旧片。录屏字幕避开操作区，见[录屏路径](screen-tutorial.md)；本字幕环节自身仍不改变声音。

本环节先建立可信的口播文字与时间基准，再完成观众看见的字幕。字幕清理不等于语音剪辑。仅要求删除字幕语气词时，保留原声、原视频与原节奏；不得顺手执行删停顿、删重录或剪声音。

## 1. 读取真实工程与现有识别结果

1. 核对本地 ChatCut 当前工程、主时间线、源视频、项目画幅/分辨率/帧率、已有字幕、文字稿与转写任务。先复用已接受的完整转写，正在识别则等待该任务；不要重复启动识别。只有文字确实缺失时才为相关口播源启动识别。
2. 读取完整文字稿和词级时间，分页直到全量完成。源片时间、时间线时间和动画局部时间分别记录。时间线已有剪切时建立映射，不假设三者相同。
3. 通过实际音频和视频复核疑似错字、专名、中英混排及意思不通处。ASR 文本不是事实来源；听不清时回放上下文、查看屏幕上真实工具/报告名称，并在必要时查一手资料。仍不能确定的词进入待核实表，不能凭空写定。
4. 保存修改前源文字稿、字幕卡、有效样式、可见字幕轨及原声片段状态，建立可回滚基线。项目存在已授权的语音剪辑时，先确定最终口播时间，再做本节的字幕精修与后续动画落位。

当前 ChatCut Desktop 的相关能力通常包括源转写检查/识别、`manage_transcript` 源稿纠错、`read_captions` 读卡、`edit_captions` 调显示；先读本机工具描述，按实际 schema 调用。Card/token ID 每次从当前工程返回值读取，不能使用示例或上一台电脑的 ID。

## 2. 分清源文字稿与显示字幕

| 对象 | 应做的修改 | 不应混淆的边界 |
| --- | --- | --- |
| 源文字稿 / source transcript | 确认的 ASR 错字、专有名词、重复书写字、大小写与标点错误 | 修正识别，不改讲师实际说话含义；不剪掉声音 |
| 字幕显示 / caption display | 经授权省略的无实义语气词、标点整理、换行和显示排版 | 显示稿可与真实口述稿不同；不用它代替源稿纠错 |
| 语音剪辑 / timeline speech edit | 开始时明确选择需要粗剪或另行授权的口误、重复、停顿清理 | 按接收与粗剪工作流执行；已粗剪或只校字幕时不能顺手删声音 |

先完成源稿纠错，再调整共享样式、分卡、显示文字和布局。源稿、剪切或共享样式变化可能重建派生字幕，旧 Card/token ID 可能失效；每次重建后重新读取，再修复分页或显示覆盖。多条源稿纠错先预检差异再提交；把修改位置、原文、改文、理由和核实依据写入校对表。

## 3. 英文与技术术语规范

- 先建“原识别 → 规范写法 → 本片含义 → 核实依据”的术语表，再全片统一。规范由语境和官方名称决定，不做机械全大写或全小写。
- 随包案例采用 **AI、FDE、API、SQL、Skills、Rico**；这是案例术语，不是要求新视频必须出现这些词。新片按实际品牌、产品、版本、命令与人名补充。
- 区分缩写、单词、产品名、文件名、代码和真实界面文字。大小写、连字符、单复数可能改变含义。引用界面/代码时保留其准确写法；必要时用解释文字说明。
- 联系整句、前后段及实际操作画面判断同音英文，不能只凭读音猜词。英语短语保留正确拼写和搭配，中文标点与中英空格保持一致、自然可读。
- 不添加讲师没说出的全称、翻译、结论或夸张措辞来“补全”字幕。数字、单位、日期、政策标题、否定和条件逐项核实。讲师口述本身若与事实冲突，记录并指出，不用偷偷改字幕制造说过正确内容的假象。
- 统一后再次全片检索规范词及常见误写，人工检查每次出现的上下文；次数对比用于找漏改和误改，不作为正确性的唯一证据。

## 4. 字幕语气词清理

固定清理 **“啊、呃、哎、唉”等无实义语气成分**。本案例还逐条判断后删除了“呀、呢”。这不等于把所有“呢、呀、吧、哦、嗯”做全局替换；保留确有疑问、回应、语义、态度、教学节奏或引语作用的内容。词表只负责召回，是否删除由语境决定。

执行顺序：

1. 全量扫描候选，列出所属卡片、前后文、原文、预期显示稿和删除理由。
2. 按语境决定，使用显示层文字编辑逐条或小批写回，不动源稿与音画。
3. 整理删除后残留的空格和标点。例如“师范、啊，小学教育”显示为“师范、小学教育”；句末“呢”被删后，根据承接关系决定逗号或句号，真实疑问仍用问号。
4. 若整张卡只有语气词，按本机工具支持的方式处理空卡或并入相邻语义单元，不能留下空白字幕，也不能制造时间倒置/重叠。
5. 全量回读与预期显示稿逐项对比。源稿与显示稿存在这类授权差异是正常的，不能为了让二者字符串相同而恢复已删除的语气词。

本案例只做字幕显示清理，源稿保留真实说出的语气词，986.8 秒音画未变。这个边界适用于新片，不复制案例数量或时长。

## 5. 已确认的普通字幕样式

以下为 Rico 课程长视频的已确认基线。其他讲师或品牌的任务另有规范时遵循其当前要求；没有新要求则沿用本基线作为起点，并实际检查新片。

| 参数 | 要求 |
| --- | --- |
| 应用范围 | 全部目标普通字幕；检查轨道继承与单卡覆盖后的有效值 |
| 文字 | 白色，清晰可读；字幕本体不使用逐词高亮或金句动画 |
| 背景 | 开启，`#6B6B6B`，**背景**不透明度 80% |
| 圆角 | 0 px |
| 描边 | 关闭，宽度 0 |
| 阴影 | 关闭，无文字阴影 |
| 高亮 | 关闭 |
| 行高 | 1.3 |
| 字间距 | 0 |
| 对齐 | 居中 |
| 方向 | 从左到右 |
| 混合 | Normal |

80% 是灰色背景的不透明度，不能把整条字幕或文字设成 80%。原始参考未规定字号、位置和背景内边距；案例沿用了其当时现有设置，不能从截图猜造“固定字号”。新片用项目实际画幅与输出尺寸确定可读尺度，优先画面下方合适位置，验证面部、手势、界面操作和边缘安全。不要照搬案例内部归一化字号数值、绝对坐标或 Card ID。

需要改字体时使用已获许可、已在本机注册的字体。本包已含 MiSans 原版四字重及官方完整许可；按[字体安装与原生验证](../assets/fonts/acquisition.md)在目标机正常注册，核实实际家族/字重，不依赖历史机器的“MiSans Rico”改名副本，也不修改字体名称表。不要将讲师卡或金句的大字号强加给普通字幕；字体缺失不能默默退回默认字体后声称一致。

## 6. 语义分卡与布局

- 按完整意思分组，跨 ASR 段理解句子；ASR 分段、字幕卡片、完整语义单元不同。
- 合并孤立短字、无意义碎片，拆开过长句与列表；人名、政策全称、技术名词及修饰关系尽量完整。不要把“见习 FDE 工程师”等拆成失去语义的碎块。
- 以实际读速和画面宽度判断，不用单一字数阈值替代阅读检查。避免一帧即逝、拥挤多行、重叠或字幕顶到边缘。
- 先应用共享基线并重新读取卡片，再按返回 token ID 拆分/合并，最后做单卡布局和语气词显示清理。一次会使分组变化的操作之后，不沿用此前 ID。
- 新增讲师圆窗或复制原视频可能自动派生一套未清理字幕。读取全部可见/隐藏字幕轨，隐藏重复派生轨，保留已校对主字幕；不要靠画面抽查遗漏双字幕。

## 7. 字幕阶段的完成检查

必须同时有数据证据和实际合成画面：

1. **全片文字回读：** 已分页读完全部卡片；与预期显示稿逐卡比较，所有差异有授权理由；术语、语气词、标点、数字与限定复查完成。
2. **结构检查：** 无空卡、倒置时间、非预期重叠、缺失段落或重复可见字幕轨；有拆并卡时记录数量变化原因。样式按继承后的有效值核对，而不只看一个轨道字段。
3. **音画保护：** 若本步仅字幕任务，比较主视频范围、播放速度、帧数/时长、原声及链接关系，确认没有剪声、剪画或改节奏。
4. **实际画面：** 查看长句、中英混排、政策/报告名称、句首/句中语气词、不同讲师姿势和后续动画附近的字幕。检查入卡/换卡边界与完整显示，确保可见、可读、不遮挡脸及重要操作；静态源画面不能代替时间线合成。
5. **保存与交接：** 回读保存后工程；在原本地 ChatCut 打开审核位置。记录“助手核查完成，用户待审核”，不把用户没反馈写成已通过。

后续源稿或剪切变化，应重新跑受影响字幕与全片术语/重复轨检查；不要只修眼前一张卡。

## 8. 最小交付记录

保存到新视频自己的项目目录：修改前后文字稿、术语表、逐条修订表、字幕显示清理表、最终卡片与有效样式、全量检查结果、实际合成画面和待核实项。输出文件使用项目相对路径；全片校对证据保留在该项目，不塞进通用 Skill 的可执行请求中。
