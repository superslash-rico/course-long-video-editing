# 讲师名签与金句包装

**当前分流：** 固定名签/金句的确认不因用户提供片头片尾和封面而重选；也不据此改用户供稿，包装仅两处首尾转场。录屏中大字/圆窗避开点击、输入、报错和结果阅读，不强制每段都加金句或露脸。口播粗剪/插入式包装改变时间后须按当前映射重新核对cues，不能只平移旧卡。

本节复用已经选定的组件语言，把制作精力优先投入解释知识的专业动画。金句与普通字幕独立；金句不能替代完整字幕，也不能用大字卡片代替应当说明关系、过程或变化的专业动画。

## 1. 决定适用身份与风格

- Rico 的已确认名签内容是 **“Rico 超级斜杠创始人”**，视觉为 A“斜杠名签”。随包代码与预览用于复现这一品牌示例。
- 新任务是 Rico 课程时延续上述已确认设计，不重新让用户选样。新任务是其他讲师时，从当前任务、实际自我介绍与明确资料确认姓名和身份，不给其他讲师冠上 Rico 或超级斜杠创始人。缺少可核实身份时保留已确认姓名或标记待补，不虚构履历。
- 金句延续 **C“大字层级”＋B“荧光批注”＋D“跟读强调”** 的文字语言。人像可沿用已确认的半透明渐隐背景；录屏的字色、衬底与位置按当前真实底色和留白重设，不能固定白字加黑灰雾场。
- 专业动画先行：先完成解释动画及其真实占屏范围，再给未覆盖的有价值内容安排金句。已存在且实际语义重复/画面冲突的金句为专业动画让位，连同它的入场声和审核标记一并处理。候选时间窗相交不能作为批量删除依据。

随包资源：名签源码见 [identity-slash](../assets/templates/identity-slash/)，金句源码见 [quote-highlight-follow](../assets/templates/quote-highlight-follow/)，字体安装与注册说明见 [fonts/acquisition.md](../assets/fonts/acquisition.md)（已附原版四字重和完整许可），视觉/运动参考见 [通用工艺示范](../assets/examples/portable-workflow/)。只以打包清单列出的当前源码和默认值导入，旧工程请求和历史回执不作为可重放模板。

## 2. A 斜杠名签

### 固定视觉与可调部分

透明底，大号白色姓名、较小浅白身份文字、紫红斜杠、渐隐细线、克制的滑入与揭示。随包 Rico 示例的设计坐标：

| 项目 | 示例值与含义 |
| --- | --- |
| 自然画布 | 640×256；这是组件局部画布，不是视频分辨率 |
| 字体 | 目标字形 MiSans，Bold 91 px / Regular 33 px，在组件设计坐标内；须目标机注册随包原版字体并核实实际家族 |
| 颜色 | 斜杠 `#E802F8`；姓名 `#FFFFFF`；身份 `#EEE9F1` |
| 入场 | 约 0.48 秒；斜线、姓名、身份依次揭示 |
| 退场 | 末尾约 0.42 秒，淡出与轻微位移 |
| 总长 | 示例 6 秒，按实际自我介绍和读时调整 |
| 可编辑项 | `name`、`identity`、`font`、`accentColor`、`textColor`、`identityColor`、`seconds` |

保持已确认的层级与间距。长姓名、长身份会改变排版；不得只改字不检查。按新视频画幅缩放/调整布局，实际检查文字完整与视觉重心；局部设计字号不能直接当成新视频的屏幕字号。

### 定位与落位

1. 读取开头实际词级时间与运动画面，定位“我是……”或同义自我介绍。根据讲述节奏让名签在介绍开始时自然出现，不能照抄样片绝对时间或帧号。
2. 选择不会遮脸、手势、普通字幕和已有信息的位置。左下字幕上方是已验证示例，其他构图需重新判断，不作为不可变坐标。
3. 按 [字体安装与原生验证](../assets/fonts/acquisition.md)在目标机正常注册随包原始 MiSans，核实 Regular/Bold 的实际家族与字重；保持 TTF 原始名称表和字节不变。再导入入口与属性 schema，使用新返回的资产/轨道/片段 ID。保留源文件与相对依赖，给素材库容量和片段时长足够范围。
4. `seconds` 与实际 `durationFrames/fps` 一致，确保尾部退场完整。不要拉长时间线片段却仍用 6 秒属性导致提前消失。
5. 使用一个短、轻、空气感的入场 whoosh；不额外加退场声音。声音感知落点通常位于入场开始后约 0.1 秒，按实际动作与声音锚点修正。

已用音色是 ChatCut 库 **Airy Short Whoosh**（可搜索 `soft whoosh` / `Airy Short Whoosh`）。库定位标识或本地注册结果由本机工具返回；不能复用旧工程媒体 ID。库的感知锚点不一定是音频片段起点，先读声音使用说明，再对齐；直接导入文件时检查前导长度，避免整段声音晚到或早到。

### 名签验收

检查出现前、斜线开始、姓名揭示、完整停留、退场中、消失后，以及讲师动作最大幅度。临时改姓名或颜色，确认可编辑参数真的改变原生合成，再恢复最终值并回读。导出带前后余量和原声的短片，实际看入场和退场、试听 whoosh 与讲话关系，不能以导入成功或电平数值代替视觉/听感审核。

## 3. 全文找金句，避免漏扫与滥用

“金句”是观众值得特别关注的内容，包括定义、判断、问题、方法、检查标准与行动，不要求像口号，也不只挑情绪强烈的句子。

1. **全文建图。** 通读已校对的完整口播，按主题与推理关系划分单元，写清整课希望观众理解什么、采取什么行动。逐段建立处理记录，不能只搜索“关键”“记住”。
2. **多线索召回。** 重复检查核心结论与定义、认知转折和必要条件、值得思考的问题、可复用步骤、检查标准/误区、课后行动与总结。跨段合成完整意思，不能按 ASR 段或字幕卡截半句。
3. **证据分层。** 每个候选保存原话、原片与时间线时间、上下文、价值理由、展示精简文案、重复主题关联、与专业动画的实际覆盖关系。每个段落记“候选/证据或例子/衔接/无需强调”的理由。
4. **忠实精简。** 原话与展示文案分开存；保留主体、对象、否定、条件、证据与适用范围。精简文案不套引号假装逐字引用。数字、政策、报告、招聘案例保留日期/来源/样本口径，不能扩大成普遍保证。
5. **专业动画后取舍。** 根据已制作动画的真实语义与画面覆盖决定保留/合并/让位。同一观点多次出现可有主次，不反复打断讲解。候选数量和展示密度由新片内容决定，不能复制案例的 59 句或最后 11 句。
6. **类型明确。** 精确摘取的金句保持原词序和真实词级锚点；概括性的知识点注明是讲解摘要，直接完整呈现，不给未说过的改写文案套虚假的逐字时间。可按需要分散安排术语、方法、前提和纠错提示，避免只强调口号。
7. **逐句编排。** 最终每句明确观众任务、精简文案、口播锚点、关键词、分行、字体尺度、实际读时、讲师安全区与唯一入场声。先确保观众读得懂，再确定视觉强调强度。

全文覆盖和取舍表提高召回并方便审查，不表示“所有有价值”存在唯一客观集合，也不能宣称一轮分析绝对无遗漏。

## 4. C+B+D 金句语言与画面适配

### 文字语言与背景分流

- C：大字层级，前提与结论有明确主次，文案简洁。
- B：淡紫荧光扫过关键词，荧光内深色字。
- D：按真实口播短语先后点亮，注意力跟随讲解，不逐字响音效。
- 人像示例的暗色光场向人像和边缘渐隐；这是人像分支，不能当作全部录屏的固定背景。录屏按[当前屏幕适配](screen-tutorial.md)选择高对比字色、局部强调和留白，避免大面积黑灰雾场。

随包人像示例设计值（不是录屏默认）：自然画布 1440×930；目标 MiSans 字形，前提 Regular 64 px、结论 Bold 92 px；正文 `#FFFFFF`、跟读 `#F4A6FF`、荧光 `#EBC4F5`、荧光内字 `#231529`、细线 `#E802F8`、背景 `#0C0A14`；背景最大不透明度 0.52；约 0.28 秒淡入、最后 0.35 秒淡出。

这些是组件设计坐标和默认值。每句重新检查行长、3—5 行等实际需要、字号与布局，不要求固定三行；长句可分成连续语义拍，不能用无限缩小字体来塞。讲师会移动和低头，必须看运动画面而非只看一张头像。文字区位置在 CSS 布局内；若需要改变布局，复制成项目自有版本后改对应源文件，不能假装当前 schema 暴露了并不存在的位置参数。

### 可编辑属性

`text`、`keywords`、`cues`、`font`、`textColor`、`activeColor`、`markerColor`、`inkColor`、`accentColor`、`bgColor`、`bgOpacity`、`transparentBackground`、`seconds`、`leadSize`、`mainSize`；另有文字区X/Y/宽、行距、未读透明度及暗场中心/半径控制，见当前properties.json。

`transparentBackground:false` 表示使用本套半透明渐隐光场；`true` 会关闭该光场成为纯透明。人像示例采用前者，不要因为属性名称就把 false 误认为不透明实底。录屏先看真实底色；浅底通常使用 true、深色文字和适合的关键词色。随包旧口播组件还含投影，必要时复制到本课再修改CSS；只关暗场、却保留重阴影或低对比白字，仍不算适配完成。未获用户确认的新视觉保留为项目候选，不替换为已认可通用模板。

### 跟读 cues 必须由新句重建

`cues` 是一段 JSON 文本，其每项包含：

```json
{"row":0,"from":0,"to":4,"start":0.12,"end":0.72}
```

- `row` 从 0 开始，对应 `text` 按换行分出的行。
- `from` 包含起始字符，`to` 不包含结束字符；字符索引按当前 JavaScript 字符串计算。标点、空格、英文和 emoji 也影响索引，不能简单拿视觉字数代替。
- `start`/`end` 是相对**该动画片段起点**的秒数，不是词级 API 的微秒，也不是整片绝对秒数。
- 每行从 `from=0` 连续覆盖至该行 `text.length`，无缺口、重叠、越界或倒置。每个 `start/end` 有限、非负、有序，且在实例时长内；先后顺序符合实际口播。可为还没说出的标点分配相邻短语，但不能抢先揭示条件之后的结论。
- 改字、去标点、换行、改变片段入点或变速后，重算所有受影响 cues。荧光关键词尽量与短语边界协调，避免一个关键词被两段切开后失去高亮。
- 源码在 cues 缺失或覆盖非法时会回退到整行显示，并标记 `cueStatus=fallback`。**完整文字出现不等于精确跟读通过。** 检查源码验证或实际运行状态，发现 fallback 要修正 cues；新句不能使用 Q018 的旧时轴。
- 随机跳到中间、倒退后再到相同时间应得到相同结果。按 `timeSeconds` 确定性计算，不能依赖已播放过的 DOM 状态、真实时钟或不可复现随机数。

### cues 结构校验与真实口播检查

将该句最终 `text`、`cues`、`seconds` 等有效值保存为新项目的实例 JSON，再从 Skill 根目录运行：

```sh
python3 scripts/validate_quote.py "/absolute/path/to/project/quote-instance.json"
```

参数替换为目标机实际实例文件。脚本只读，退出码 0 表示结构检查通过，2 表示需要修正；不写回工程。它检查非空最终分行、UTF-16 字符半开区间与代理对边界、逐行连续完整覆盖、有限且非负的局部秒数、结束不超实例时长，以及按最终文本阅读顺序没有时间重叠或倒退。包含 emoji 等非 BMP 字符时，不得用 Python `len()` 直接生成 JavaScript 索引。换行、文案或片段入点变化后重跑。

**脚本通过不代表声画同步或跟读节奏通过。** 仍需读取真实词级时间、原生预览短语点亮、连续回听原声与入场声；检查条件/结论顺序、口播提前量与读时。运行状态无 fallback、结构通过、真实合成可读、实际听看自然，四项分别记录。

组件逻辑行允许自动折成多个视觉行，须将最终显式分行与实际排版逐一对照。长行/中英混排/数字单位/emoji及标记padding可能改变行数；不要把UTF-16结构通过当作排版通过。用[排版回归素材](../assets/records/quote-layout-regression.json)和本片实际字体复查，必要时重新显式换行并重算cues。缺真实音频/词级锚点的estimated cues只作准备，不通过精确跟读验收；详见[准备与预览分支](partial-inputs-and-design-previews.md)。

### 容量、默认时长与片段时长分开

示例曾将导入资产容量扩展为 20 秒，用来容纳较长实例；示例默认仍是 5.2 秒。20 秒不是每句默认占屏时长，5.2 秒也不适用于所有句子。

每句按 `durationFrames` 与实际项目 `fps` 计算 `seconds=durationFrames/fps`，保证不超过已注册容量，且退出动画完整。素材容量不够先扩容或重新导入，不把截断的退场当作完成。帧、秒、微秒显式换算；不同帧率按秒重算，不复制 30 fps 的帧数。

## 5. 金句只保留一个入场音效

**每处金句只在出现时配一次入场音效。退场、结论和最后一个跟读短语均不加“叮”或其他结束提示声。** 这是明确固定的决策，覆盖早期双音效演示。

已用音色为 ChatCut 库 **Deep Short Whoosh**。当前包不因能读到旧源 MP3 就默认转授其再分发权；按包内素材许可与声音说明在本机库合法获取，或用已明确可分发的自制候选提示音试听替代。自制候选并非用户已认可音色，应如实标记，最终以原声合成听感确认。

音量按新片讲话和音效源的响度、频段与实际播放设备调节。案例早期主重点 -18 dB、次重点 -22 dB，随后全片声音又有增强，这些都不是跨片硬性增益。先让动作可感知，又不盖住辅音/尾音和讲解；数值无削波不能保证声音合适。短音效保持独立角色，不误设成持续背景音乐或靠自动压低掩盖不合理音量。

删除或替换金句时，查全部相关轨道与资产引用，连同对应入场声音及审核标记一并更新；不能只静音某一轨遗漏其他轨的历史叮声。旧含 Clean Ding 的选样视频、混音、请求和素材是历史，不能作为当前默认或直接重放。

## 6. 原生合成与全片检查

1. **代表句先验：** 选短句、长句、中英混排、不同姿势各一；检查未出现、淡入、跟读中段、完整结论、淡出、消失后。讲师面部、手势、普通字幕与重要操作在这些时刻均安全。
2. **全部实例回读：** 确认每句文本、关键词、cues、字体、颜色、实例时长、覆盖值、声音数量与落点正确，无重复创建、预检残留或历史叮声。默认值和单实例覆盖合并比较有效参数。
3. **每句实际画面：** 全部句子的完整状态与跟读中段至少检查一次；长行、镜头/人物移动、与专业动画相邻的句子补查边界和运动最大幅度。不能以少量代表句代替全片实例检查。
4. **可编辑与恢复：** 在测试实例临时改文字/关键词/荧光颜色，确认原生画面变化；恢复交付值并回读，不能留下测试覆盖。
5. **连续视听：** 导出带前后余量的真实原声审核片，检查进入、阅读、退出、金句与专业动画衔接和声音。核实实际输出编码、帧率与色彩；未经色彩转换的 HDR 抽帧只用于结构时机，不用于断言颜色一致。
6. **保护与交接：** 若本轮仅包装，原声、普通字幕、视频节奏保持；比较修改前后工程状态。保存真实回执、画面和可编辑源码，打开原本地 ChatCut 供审核，记录“待用户听看”，不自动写成已批准。

## 7. 跨电脑复用

- 完整复制各组件入口及其相对 CSS/JS；源文件放在新项目持久目录，不能放临时下载目录后又清理。
- 本包配套 MiSans 原版四字重、官方完整许可、[字体安装与验证说明](../assets/fonts/acquisition.md)及需求清单。目标机依附带许可，按本机 ChatCut 字体能力正常注册，再按 schema 导入组件。历史项目的“MiSans Rico”是本机改名副本，不能作为跨机依赖，也不指导重新修改 name 表；包内默认 `font` 用 MiSans，实际注册后的家族/字重仍需回读并渲染验证。若使用合法替代，明确记录外观差异并重新排版，不把缺字 fallback 当作复现成功。
- 新工程重新导入媒体和声音，重建资产绑定、轨道、标记，使用新返回 ID。旧项目设计规范也不是跨电脑可访问资源；从包内文档和 portable 元数据重建。
- 创建一条短真实口播测试，验证字体、透明合成、可编辑属性、随机跳转、实际导出和音效，然后继续完整制作。新素材、新句子的时间码、布局和读时仍必须重新设计。
- 本节组件可以固定复用；专业动画只复用合适的底层实现、材质与经验，每段的整体构图、叙事与镜头重新思考。不能把名签/金句套版当作专业动画质量。
