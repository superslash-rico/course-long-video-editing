# 跨电脑环境、迁移与首次试用

**v1.1新增能力按任务检查：** 需粗剪时读取当前语音剪辑/脚本工具及真实音画；已粗剪不因缺剪声工具而阻塞字幕。导入用户片头片尾与首尾转场须当前运行时支持；封面只需能实际打开用户文件，不依赖封面生成模型或渲染工具。`validate_covers.py`和`rebuild_manifest.py`均用Python标准库；无Python时仍可人工检查/维护，不能假称脚本已运行。当前发布源不依赖原作者全局路径。

本技能包提供工作法、项目规范、检查表和随包参考。它不把另一台电脑变成本机的副本，也不包含原课程工程、账户、全局配置或私有模板下载包。**文件齐全、能导入、能导出、达到审美标准，是四件分别要验证的事。** 按具体证据写清在哪台机器验证了什么，跨机原生结果待实测；新整体设计工作法尚未完成新片验证，不用笼统的“本项目已验证”覆盖这一边界。

## 1. 分清三层依赖

| 层次 | 必需条件 | 如何确认 | 不应假设 |
| --- | --- | --- | --- |
| Codex / 其他兼容 Agent | 能读 `SKILL.md`、相对引用和本机工作目录；能调用当地已启用的 ChatCut Desktop 集成 | 查看本会话实际附加技能和工具；读当前工具说明与 schema | 复制文件即已启用；旧会话的工具名、路径、权限在新机器仍相同 |
| ChatCut Desktop 原生编辑 | 本机已安装可用 Desktop，原生集成连接正确，素材可读；运行时支持所选 MG / pixel processor | 原生读取目标工程，导入本地探针，回读保存状态、合成预览与导出 | 网页插件等同本地 Desktop；任意 npm 包、Node API 或联网 import 可在动画渲染器运行 |
| 外部服务和素材 | 只有实际用到云转写、字体下载、库检索、网页、生成音效或其他生成时，才需要各自网络、授权和额度 | 读取该能力当前状态与实际返回结果 | 本地程序存在等于已登录；账户已登录等于全部生成有权调用；原生剪辑本身必须依赖所有外部服务 |

Python 只是运行随包检查脚本的可选辅助工具。缺 Python 时，可逐项人工执行本文件；不要因此认定 ChatCut 不能编辑。ffmpeg / ffprobe 是可选的独立媒体检查工具，不是使用原生 ChatCut 剪辑或导出的先决条件。Node / npm / Remotion CLI 也不是原生 MG 播放的必备安装项。所需模块应以当前原生运行时和原生验证为准。

## 2. 安装与目录

1. 解压完整技能目录，保留 `SKILL.md` 与下属文件的相对位置。不要只发送入口 Markdown。
2. 根据接收方 Agent 的当前技能安装方式，放到其支持的用户或项目技能目录。使用该 Agent 的技能发现界面或本会话技能清单验证确实加载。不能仅凭一个固定旧版本路径认定安装完成。
3. 先按[标题与日期目录](project-start-and-file-management.md)在实际项目工作区建立`YYYYMMDD-课程标题/`及五类素材目录，区分工作区根和本课根。素材、源码、日志和输出统一放本课；技能包只读，不把范例直接改成本片。初始化助手只用Python标准库，分类清单由当前任务产生。
4. 所有路径由当前技能根、新项目根和实际工程路径推导。技能资源从 `SKILL.md` 所在目录解析；脚本使用自身 `__file__` 定位，不能依赖启动时的 cwd。
5. 原生工程 UUID、timeline / track / item / asset ID 只在当前工程读取后使用。范例中的 ID 或媒体绑定只解释旧案例，必须为新工程重新导入、绑定和验证。

检查包与本机线索：

```sh
python3 "/接收位置/course-long-video-editing/scripts/check_environment.py"
```

Windows 可用本机 Python 启动方式（如 `py -3`）；示例中的路径由接收方替换。脚本可从任意 cwd 运行，也接受 `--skill-root "/另一个技能目录"`。输出是 JSON，退出码 0 表示所请求的**文件/静态检查**未发现阻断项；2 表示有阻断项。0 不证明 ChatCut 已连接或画面合格。

只允许读取技能副本、不能检查宿主环境的隔离审查中，使用：

```sh
python3 "/接收位置/course-long-video-editing/scripts/check_environment.py" --package-only
```

此模式只检查技能根下的必需文件和资源 manifest；不发现宿主字体、应用、PATH 程序、启动器或工具清单，也不读取宿主平台信息。默认模式继续提供本机环境线索。`--package-only` 可与 `--skill-root`、`--required` 同用；与 `--launcher`、`--font-dir`、`--tool-manifest`、`--require-native-tools` 冲突时会在读取任何宿主线索前明确拒绝并退出 2。

## 3. 发现原生能力，避免误入网页工程

**优先使用当前会话已经连接、说明明确为 Desktop 的工具。** 阅读当前服务器说明、工具 schema、返回的原生专用技能。工具命名空间可能变化，不能把本案例用过的某个前缀作为平台判据。

首次至少完成：

1. 原生读取当前选中工程；没有目标时列出本机工程并选择用户指定的工程，或在已授权的任务中创建新工程。
2. 回读工程名称、路径、画幅、分辨率、fps、时间线、媒体离线状态。不要从浏览器 URL、聚焦窗口或旧日志推断操作目标。
3. 读取当前工具清单与具体 schema，确认具备目标工作所需的等价能力：工程读取和选择、素材导入、时间线/合成画面预览、条目/资产回读、字幕读取编辑、MG 导入及放置、导出与进度查询。旧名仅作检索线索，当前 schema 才是调用依据。
4. 只存在 hosted / web 工具时，不得静默改用它编辑本地草稿。先区分本地与网页表面。原生失败不等于草稿丢失，也不等于账户必须重新登录。

本项目过去使用过的 Desktop 操作线索包括 `get_active_project`、`read_project`、`preview_timeline`、`read_captions`、`push_asset`、`inspect_asset`、`inspect_item`、`edit_item`、`export`、`track_progress`。这是历史能力名，**不是冻结 API 合同**。

### 仅在缺少连接时恢复

检查本机已安装 ChatCut 提供的官方 Agent / MCP 集成入口与当前官方说明。若有本机官方启动器，使用其返回的初始化说明和动态 `tools/list`；不要复制原作者的桥接脚本、绝对路径、端口、token 或整个 Codex 配置。

macOS 的历史发行版曾把官方启动器放在当前用户的 `Library/Application Support/ChatCut/chatcut-mcp`。这只是有界查找候选，不能作为所有版本、Windows、Linux 的安装承诺。其他平台依据当前安装位置、官方集成导出或用户明确提供的启动器路径发现。随包脚本允许 `--launcher` 检查明确路径的存在与可执行性，但**不会运行它**。

不要扫描或打印 `auth.json`、Cookie、Keychain、`.env`、token、账户 API Key 或完整全局配置。不要自动注册服务器、修改配置、安装依赖、下载或登录。恢复实际缺失的连接时遵循接收方 Agent 的权限机制，保护现有配置。已连接就不重复安装。

## 4. 运行时与源集完整性

- 在新工程工作目录保存一个完整 MG 源目录：入口、相对 import 的模块、图像/纹理和其他本地依赖必须一起保留。原生导入可能保持源码链接；删除或移动源目录可能使以后预览/导出失败。
- 读取当前官方 `create-motion-graphics` 运行时文档后再写代码。`.tsx` / Remotion 与 HTML 的 lifecycle、模块可用性不同。不要用互联网 CDN 或开发机的 `node_modules` 隐式补齐。
- 以真实绑定做原生验证。需要真实素材时，重新导入到新工程并使用其返回 ID，或按当前官方运行时支持的本地资源机制绑定。不要把原作者文件路径或工程媒体 ID 留在新动画里。
- fps 从实际工程和运行时读取。Remotion 使用 `frame / fps`，HTML 使用宿主提供的时间；30fps 与 60fps 的相同秒应得到相同动画状态。不得硬塞一个 30fps fallback 来掩盖兼容问题。
- 跳转、倒放寻帧、连续播放和导出必须重建同一状态。暂停独立 ticker；不要让 Math.random、系统时间、CSS 自播放或上一帧状态决定结果。
- 圆形讲师窗如使用 pixel processor，必须原生处理**当前真实输入**，依据新片人物位置重设裁切与路径；不能照搬上一片的坐标、原片 sourceIn 或固定右下角位置。
- 新机器导入一个最小探针，再用真实字体、中文长短句、真实图片和动态属性覆盖做实际场景验证。原生源码验证通过只证明技术接入，不证明视觉成功。

## 5. 字体、视觉资源与授权

随包品牌资源与参考视频依其各自附带授权和边界使用。**v1.0.1 已在 `assets/fonts/` 配套 MiSans 原版四字重及官方完整许可**，字体二进制和版权保持不变。MiSans 是本项目确认过的字体方向；接收方阅读附带许可，按[安装说明](../assets/fonts/acquisition.md)在自己的电脑注册，官方补充入口为[字体页](https://hyperos.mi.com/font/zh/download/)。**名称存在、文件存在和原生实际用此字体渲染是三层证据**。环境检查器只发现字体文件名线索；包验证器额外核对随包文件摘要、实际字重和许可，但都不能证明原生字体已注册或保证中文字形覆盖；旧机器出现过的别名不能自动满足新机器字体依赖。

1. 按 `assets/fonts/acquisition.md` 和 `requirements.json` 使用随包四字重，阅读官方许可并依系统或 ChatCut 当前流程注册。安装技能只复制资源；字体注册和原生渲染另验，不自动安装系统字体，也不改写字体名称表。
2. 原生字体目录/搜索、系统字体与支持的在线字体目录由当前版本决定。可能需要网络下载或缓存；失败时可能静默 fallback。不要用浏览器 CSS 字体截图代替原生字形检查。
3. 用本片实际中英文字、标点、数字、品牌名与最长标题做合成预览；对照参考检查字形、粗细、断行、字宽和标点，导出同一帧再核对。
4. 不能使用确认字体时，选择有合法来源且覆盖字形的替代，重新调整排版，记录变化；需改变用户确定品牌外观时说明这一差异。不要把自动 fallback 记成“已复现 MiSans”。
5. 外部模板只借鉴合适的设计和运动。MotionGit 私有下载原包、账户 API Key、私有 acquisition 注册、登录状态和缓存不随技能发出。接收方若需要购买/下载，应以自己的合法账户获取；模板可用性不作为核心流程的强制依赖。

先确认当前搜索/浏览器控制/电脑操控/截图能力与新片资料，按[素材工作流](material-research-and-capture.md)实际检索采集；用户无材料也执行。不能取得真实软件画面时保留具体缺项，不用生成界面冒充。生图只在合适且当前能力可用时补充插画，不把某个云账号或额度当必需条件。

学生PDF优先现有`superslash-brand`与PDF技能；没有品牌技能可用随包[课程资料模板](../assets/templates/course-companion/使用说明.md)。可选生成器需要ReportLab/Pillow，原版MiSans和两份官方Logo已随包；PDF渲染可用Poppler或接收机已有等价能力。按当前环境发现依赖，必要时在项目隔离环境准备，不改全局配置。PDF字体直接从包内嵌入，不替代视频端的原生字体注册检查。旧的“连接恢复不自动安装依赖”不妨碍在已授权资料制作中按宿主权限准备项目依赖。

## 7. 新电脑首次试用：分阶段通过

### A. 包完整性与发现（静态）

- 从与技能目录无关的 cwd 执行检查器，确认相对资源可定位；检查包内必需资源/哈希。
- 记录操作系统、ChatCut 当前版本（从应用/当前原生说明读取）、Agent 类型、当前工具能力、实际字体来源、外部网络能力。
- 按“存在 / 不存在 / 未实测”记录，不把可选工具缺失当作失败，不把静态发现当作端到端成功。

### B. 最小原生闭环（真实新工程）

1. 导入自己的新视频，回读帧率、分辨率、时长和源映射；不复用本课程媒体 IDs。
2. 转写/读取字幕，校对一段包含英文、语气词和长句的实际口播；应用品牌字幕样式，回读显示稿，并检查人物与字幕通路。删除字幕语气词不应擅自删声音。
3. 做一个讲师卡和一个金句实例，改一次文字/颜色属性，再恢复；检查保存默认值、实例覆盖和画面确实联动。
4. 选一段约 15–30 秒、能解释完整关系或变化的内容，按“整体构图与镜头设计工作法”从全景设计到细节，再制作。不要用原片照搬模板冒充新内容验证。
5. 检查开场全景、结果全景、所有阅读落点、最大运动幅度、遮挡/裁切风险、人像切换及出场；倒跳再顺播，导出与当前合成比较，试听入场和动作音效。
6. 修改一个公开可编辑参数后重导短段，确认预览与导出使用实际保存值；恢复到最终设计，保存源码和审核证据。

### C. 一个完整长视频（接收方真实测试）

- 理解全文后先完成素材需求与真实来源采集，再排专业动画覆盖，再安排未覆盖内容的金句；保护口播顺序、原声和时间映射。
- 每个专业动画独立完成内容、全景、细节、分镜和声画设计，自查后才向后批量扩展；不能因组件编译过就默认每个长短文案都通过。
- 在本机原生 ChatCut 中连续审核所有动画及接点，完成可编辑工程、源码、当前素材清单、日志和预览；实际导出是什么 codec / 色彩就如实记录。
- 剪辑定稿后实际生成课程标题/简介与品牌学员PDF，回读与最终内容的一致性，逐页查看、核字体/链接；模板能运行不等于本课资料通过。
- 由原作者或目标观众审核全景美感、信息解释、细节与镜头节奏。通过技术检查仍需区分“制作完成待审”与“用户认可”。

成功记录至少包括：新视频来源、各段真实时间码、原生工程标识（仅本机记录）、字体验证、素材绑定、可编辑参数证据、全景/特写/运动极值/出场证据、连续试听与导出结果、用户反馈。没有覆盖到的形态（如真实三维、复杂环绕、在线生成）单列“未覆盖”，不因一个简单场景成功就宣称全面兼容。

## 8. 问题时按层定位

| 现象 | 先检查 | 不要直接做 |
| --- | --- | --- |
| 工具显示登录失败 | Desktop / hosted 表面、当前连接、当前原生错误；是否只是外部服务登录 | 强迫重新登录所有账户、覆盖原工程或账号配置 |
| 源码能预览，时间线不变 | 实际 asset 路径、保存 schema/defaults、实例 overrides、放置层级、当前工程/时间线 | 反复新建工程或断言缓存问题 |
| 换电脑图片丢失 | 新工程导入是否成功、ID 是否重绑定、相对资源是否随源集保留 | 把旧 ID / 本机绝对路径硬写回来 |
| 字变宽、长句裁切 | 原生字体实际渲染、字重、fallback、最长真实内容、镜头焦点 | 只缩小所有内容，或牺牲全景构图掩盖问题 |
| 顺播与跳转不同 | 独立 ticker、前帧依赖、随机数、异步未完成、fps 时间单位 | 仅录屏掩盖确定性错误 |
| 导出色调和截图不同 | 实际编码、色域 / transfer、播放器色彩管理、原生合成帧 | 把普通解码图偏暗直接当成素材调色失败 |
| 本机工具/平台不支持所需处理 | 当前官方原生能力、等价形式或可验证的中间视频方案 | 承诺未运行的高级功能，或未经说明切到网页工程 |

## 9. 随包检查器边界

`scripts/check_environment.py` 仅用 Python 标准库，默认只读、不联网、不运行外部程序、不启动 MCP、不修改应用和配置。可选参数：

- `--skill-root PATH`：检查另一个完整技能目录。
- `--package-only`：仅检查包内文件与资源 manifest，跳过全部宿主发现；适用于只允许读取技能副本的隔离审查。
- `--launcher PATH`：显式提供本机官方启动器，检查路径与可执行性。
- `--font-dir PATH`：补充有界的字体文件查找目录，可重复。
- `--tool-manifest PATH`：读取由当前会话合法取得的 `tools/list` JSON，仅检查工具名称集合；不解析账户配置。快照不证明此刻在线。
- `--require-native-tools`：要求提供的清单包含历史能力名；缺少时退出 2。若当前版本改名，人工按动态 schema 核对等价能力，不能以此旧名清单否定新版。
- `--required RELATIVE_PATH`：给静态包检查追加必需文件，可重复；必须位于技能根内。

脚本在 `assets/manifest.json` 存在时，逐项检查 `files` 内的包内相对路径、文件存在、声明字节数与 SHA-256；拒绝逃出技能根的路径、Windows 盘符/反斜杠路径及指向包外的符号链接。`externalRequirements`（包括接收机字体注册与真实渲染）单列未实测，不下载也不把不存在的外部资源当成包损坏。完整引用与安全检查再运行 `scripts/verify_package.py`。

报告不应包含密钥。脚本不验证登录、积分、原生 GPU/字体内部字族、MCP 是否在线、视频可读性、实际导出能力或审美质量；这些保持 `unverified`，通过上述真实闭环补足。
